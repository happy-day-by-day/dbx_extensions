# DBX 数据库文档插件

Svelte 5 + Vite 界面及内置快照存储后端，在 DBX 中浏览数据字典、查看字段 / 索引 / 约束、生成参考建表 SQL、导出 Markdown。当前版本 **0.4.39**，macOS / Windows / Linux 安装同一个 `.dbxp`，无需宿主补丁或额外运行时。

## 连接和数据库

切换页使用全宽列表，统一展示所有已保存文档的数据库名称、连接名称、本地缓存状态、表数量及最后成功同步时间。当前文档单独标记；列表使用紧凑间距，行高由内容决定，长名称按需换行；窄屏将连接名称和同步时间合并至行内。点击「数据库」「连接名称」「最后成功同步」表头可在本地切换升降序；名称按自然顺序比较数字，同步时间首次点击按最新优先，无成功记录始终置后。搜索、筛选和刷新列表时保留当前排序，窄屏通过排序下拉框选择；排序不读取数据库或修改缓存。

支持按数据库或连接名称搜索，以及「全部数据库 / 有本地缓存」筛选。点击文档优先读取本地缓存；点击「刷新列表」只重读本地记录和缓存摘要，不查询数据库、不更新同步时间，也不清空筛选条件。返回或重新选择当前文档保留浏览状态；批量成功生成后返回会重新加载本地文档。

有缓存的库在列表右侧提供清除图标，确认框展示数据库及连接名称。清除仅影响该连接、数据库、类型的本地文档与最后成功同步时间，保留列表记录，其他库不受影响，也不访问数据库。清除当前文档时同步移除内存中的旧内容；之后可手动刷新重新生成。快照文件原子替换为小型删除标记，阻止旧 UI 缓存或旧 `.cache` 文件在重启后重新导入；旧版副本用于兼容恢复，不作为已清除文档恢复来源。写入失败或并发修改冲突时保留原缓存，可重试；同步期间禁用清除。

顶部「批量生成文档」打开独立弹窗，读取 DBX 当前已建立连接的数据库目录，不局限于已有缓存或最近打开的文档。新库生成整库离线文档，已有文档更新缓存；本地入口不再限制最近 8 项。批量任务只使用本次数据库目录确认的库名，不将历史文档名称或连接默认库无条件并入任务，也不使用历史名称尝试连接。目录读取异常会单独显示，部分成功时仅生成已确认的数据库；整个目录读取失败或不支持时不创建该连接的任务，保留全部原缓存。基础会话关闭时只尝试使用连接配置的默认库重新读取目录。开始生成后逐库确认精确数据库会话；未连接、会话未打开或不支持的数据库跳过。弹窗展示每库表级进度、成功、失败及跳过结果，可完成当前库后停止后续生成。

每个数据库整库完整读取并保存成功后才替换该库缓存、更新最后同步时间。读取失败、元数据不完整或存储失败均保留原缓存；一库失败继续其他库。数据库逐个更新，所有元数据查询仍共用最多 4 条并发预算。

MySQL / MariaDB 自动枚举排除 `information_schema`、`performance_schema`、`mysql`、`sys` 及 `__cdb_recycle_bin__`。查询及返回结果均按完整库名进行大小写不敏感的过滤；批量执行时再次检查，系统库不参与探测或生成。文档选择列表也复用此规则，历史记录、当前上下文或快照恢复索引中的系统库不会显示，刷新及重启后均生效，无需连接数据库。相似名称的业务库正常保留，目录分页不受过滤影响；普通业务库清除缓存后仍保留入口，历史数据和快照文件不自动删除。

文档页内的「刷新」单独同步当前整库，需要 DBX 已打开对应数据库会话。常规打开、搜索、导出及本地列表刷新均不读取数据库。列表名称使用 DBX 提供的名称，页面不再提供连接名称编辑。

文档工作台顶部入口及标签显示实际数据库名称，标签格式为「库名-数据库文档」；连接名称作为辅助信息。旧宿主缺少标签标题接口时仍可正常浏览。

## 离线查看

打开文档直接显示本地缓存，不自动探测或查询数据库。无缓存时提示点击刷新创建文档。仅点击刷新后，遍历整个数据库的所有表，将字段、注释、索引、约束保存到所选目录的快照文件，无需逐表打开，无 128 张表限制。缓存按连接、数据库和类型隔离；重新打开工作台仍可使用。只保存结构元数据，不保存业务查询结果。所有查询共用最多 4 条并发队列，离线文档压缩保存到用户选择的快照目录，绕开 UI 存储每项 256 KiB / 总量 1 MiB 的限制。旧 UI 缓存可迁移到快照，原副本保留；迁移失败继续读取旧副本。页面显示同步进度、未完成数量、逐表失败原因和重试入口；同步完成前请保持连接和工作台打开。目录达到宿主上限时自动分页读取；未能完整读取时明确提示。

打开时及日常浏览始终使用本地缓存；刷新期间继续展示上次成功的完整缓存，新目录和表详情仅在内存暂存；整库同步及保存全部成功后一次性替换。刷新失败、部分表失败或保存失败均保留原目录、字段、索引、约束及成功时间，重新打开也不变；首次同步失败不会保存半份文档。页面显示「本地缓存」标识，点击可查看最后同步时间、当前表更新时间和刷新入口。最后同步时间仅在目录未截断、全部表结构完整读取且最终缓存保存成功后更新，刷新失败或部分失败保留上次成功时间；旧版缓存缺少成功记录时明确显示未知，并提醒内容可能已变更；未缓存的表显示连接读取指引。离线时可浏览已缓存详情、生成建表 SQL、导出本表，目录搜索直接从本地缓存匹配表名、表注释、Schema、字段名和字段注释，不访问数据库。字段名不区分大小写，支持中文注释、匹配摘要、高亮与 Schema 筛选；整库或当前 Schema 导出也直接从本地缓存生成，无需连接数据库；文档标注缓存来源与目录缓存时间，缺失缓存的表在界面与文档中单独列出，可保存已缓存部分。

恢复方式：在 DBX 连接树中连接对应连接并打开目标数据库，返回文档点击「已连接，刷新」或顶部「刷新」，重新读取目录并同步全部表。刷新失败保留缓存；单表失败或信息不完整时显示同步未完成，可重试。数据访问授权被拒时仍显示授权恢复提示。宿主不支持存储或保存失败时会明确提示无法持久保存离线文档。

## 浏览和检索

- 全局顶部采用单行紧凑布局；表名、复制、浏览历史和表操作合并在同一行，注释保留单行摘要。完整表名、注释、Schema、存储引擎和排序规则可从「表信息」展开，浮层不挤占字段列表；可再次点击、按 Escape 或点击其他区域收起。
- 左侧目录使用虚拟滚动，按视口加载行；支持名称 / 字段数排序。普通搜索默认匹配表名、表注释、Schema、字段名和字段注释，无需单独开启字段搜索。
- 命中表显示字段摘要和匹配数量，表名、注释与字段关键词高亮。长字段注释优先显示命中附近的文本；点击字段匹配结果后打开字段页并展示全部字段，仅高亮对应字段名和注释。右侧手动搜索独立控制字段筛选，清空后恢复目录关键词高亮。
- 文档字段搜索立即匹配内存中的本地缓存，中文输入组合期间暂停搜索；关键词、Schema、连接或数据库变化时忽略旧结果。加载、失败、截断分别提示，失败可原地重试。正则模式仅匹配已加载的表名、表注释与 Schema，并显示范围说明。
- 开启「字段搜索」后，字段名或字段注释命中的表会进入搜索结果并标注「字段匹配」。字段搜索使用普通文本，在线查询 300ms 防抖、离线搜索直接读取本地缓存；正则模式仅用于目录文本，不向数据库发送正则查询。
- 搜索与 Schema 筛选保留当前详情。点击「清除筛选」可重新定位当前表。
- `Ctrl / ⌘ K` 聚焦目录搜索；上下键选择表，目录获得焦点时 `Home / End` 到达首尾。
- 目录标题行提供轻量的「单表 / 多表」切换。多表模式直接点击表行选择或取消，以背景和文字颜色标识已选表；选择后，右侧以全宽紧凑布局按目录排序连续展示，支持全选当前搜索结果与清空；搜索或 Schema 筛选保留已选表，跨 Schema 同名表分别选择，切换数据库清空选择。每张表独立搜索字段、切换结构页签、查看建表 SQL 和导出；外键关联表会加入已选列表并定位。多表使用统一纵向滚动，较远的文档按需加载，缓存缺失只影响对应表；日常查看直接读取本地缓存。
- 多表文档以边框、标题底色和间距区分每张表；顶部单行「已选表」下拉框显示 Schema、表名与注释，支持快速定位及上一张 / 下一张跳转。手动滚动同步当前位置，搜索和 Schema 筛选不缩减跳转列表，遵循系统减少动画设置。
- 单表模式单击目录表查看文档；双击表或在目录中按 `Enter`，新开独立「表查询」插件标签页，默认填入 `SELECT * FROM 对应表;`。查询绑定当时的连接、数据库与实际 Schema；按数据库类型引用标识符，支持保留字、特殊字符及跨 Schema 同名表。
- 详情顶部支持上一张表 / 下一张表，也可使用 `Alt + ← / →`。返回时恢复原来的表和字段 / 索引 / 约束页签；跨 Schema 同名表按实际身份记录。历史最多保留 50 个位置，仅属于当前连接与库，切换资源后清空。
- 点击外键关联表直接打开目标的字段页，返回可恢复原来的约束页。DBX 同库表右键入口保留目录搜索和浏览历史，不重新初始化工作台。
- 已打开文档的刷新失败时保留当前表、字段、搜索及浏览位置，在顶部显示原因和「重试刷新」。首次读取失败有缓存时进入离线查看，无缓存时显示错误页；数据访问授权被拒时仍进入授权恢复页。
- 目录宽度可拖动或用分隔线的左右键调整，宽度和搜索偏好保存在插件独立的宿主存储中。
- 目录的高级选项收在「筛选」中，显示已开启的选项数量。多 Schema 数据库在目录中选择范围。
- 详情分为「字段 / 索引 / 约束」页签。字段支持局部搜索、无注释筛选和紧凑密度；紧凑开关统一应用于单表、多表，并在重新打开文档后恢复上次选择；字段表单独滚动并固定表头。联合索引、联合外键按名称分组，展示字段顺序、方向、表达式和引用关系。外键可跳转至当前目录内的关联表。
- 索引使用紧凑表格，每个索引一行，展示名称、类型、键字段顺序与方向、索引方法和完整注释；包含字段、表达式、前缀长度和过滤条件分别保留。支持直接从缓存搜索索引元数据、复制索引名，点击字段的索引标记可定位相应索引。多表的索引搜索相互独立，窄窗口在表格内横向滚动。
- 明暗主题实时跟随 DBX，颜色和字体优先使用宿主 tokens。窄窗口采用上下布局，可以收起目录增加详情空间，`Ctrl / ⌘ K` 会展开目录并聚焦搜索。
- MySQL 目录字段数先按库分组汇总，再与表清单关联，减少按表重复读取元数据。

## 入口和权限

| 入口 | 行为 |
| --- | --- |
| 连接右键 → 查看数据库文档 | 已指定数据库时直接打开目录；否则在同页选择数据库 |
| 表右键 → 查看表文档 | 打开目录并定位该表，跨 Schema 同名表按 Schema 区分 |
| 工作台入口 | 在同页选择最近使用的连接和数据库；首次使用需先通过右键入口进入 |
| 表目录双击 / Enter | 新开表查询标签，预填 SQL，保留原文档与其他查询草稿 |

插件使用官方 [DBX 插件 API](https://dbxio.com/cn/docs/plugin-development)，要求现有 Host API `^1.4`，不需要目录扩展补丁。初始化等待 `dbxPlugin.ready`，读取 `dbxPlugin.context` 快照，同时检查运行期能力位。快照后端使用既有 sidecar protocol v1，通过 `dbxPlugin.invoke` 调用。

所有数据库请求使用宿主只读查询接口，只复用 DBX 已打开的连接和数据库会话。首次访问某个连接时由 DBX 征求数据访问授权；打开插件不会后台探测历史连接。授权被拒时会显示恢复指引。`host.workbench` 权限用于打开本插件的表查询标签页。批量生成增加 `host.connections:read` 权限，通过 `connectionsApi` 与官方 `getConnections()` 读取连接状态；旧宿主不支持时提示升级，不探测历史连接。

## 表查询

打开查询页只准备 SQL，不自动读取表数据。可编辑 SQL 后点击「执行查询」，或在编辑器中按 `Ctrl / ⌘ Enter`；查询走官方 `queryData` 只读接口，最多返回 200 行。结果支持横向 / 纵向滚动、固定表头与 NULL 显示；空结果、读取失败、会话关闭及截断均有明确提示。编辑 SQL 后已有结果标注来自上次查询。

当前官方插件 API 未提供打开 DBX 原生 SQL 编辑器的方法，因此使用 `openWorkbench` 打开本插件声明的查询页；每次创建独立草稿，SQL 与业务结果不写入插件存储。旧宿主缺少导航接口时会在目录显示原因；查询能力缺失时仍可复制 SQL。

## 导出和复制

- 详情中的「导出本表」默认选择当前表；顶部「导出文档」默认选择整个数据库或当前 Schema。
- 导出范围由目录中的 Schema 筛选确定，不受当前选中表所属 Schema 或目录搜索词影响。
- 在线整库导出采用两表并发，固定开始生成时的连接、数据库、表清单和 Schema 范围；显示完成数与百分比。停止后不再派发新任务，等待在途读取结束并保留已完成内容。
- 结果区区分已生成、读取失败和尚未读取的表。支持「重试失败的表」和「继续生成剩余表」，仅查询未成功的表；成功结果按原始范围顺序合并，不重复读取已完成的表。
- 会话关闭或授权被拒时停止派发后续任务；其他单表错误仍继续读取剩余表，恢复后可补全未读取部分。
- 不完整或停止的导出先展示结果，可补全、复制或明确保存已有部分；补全后保存更新后的文件。全部读取失败时保留具体表名和错误，仍可恢复后原地重试。首次生成完整文档时仍直接进入宿主保存流程。
- 表清单被截断、元数据不完整或导出中断时，界面和文档会保留相应提示。
- 保存通过宿主 `fileTransfer` 写 UTF-8 字节，支持中文、emoji 和分块偏移。取消保存与保存失败分别反馈，文档仍可复制或再次保存。
- 复制表名、字段名、SQL 和 Markdown 通过 `dbxPlugin.copy` / 宿主剪贴板 API，不依赖沙箱中的 `navigator.clipboard`。
- SQL 是依据元数据重建的参考结果，执行前需核对数据库版本与完整约束。

## 支持范围

| 数据库 | 完整目录与文档 | 参考 SQL |
| --- | --- | --- |
| MySQL / MariaDB | 支持，索引查询兼容旧版本无 EXPRESSION 的情况 | 支持 |
| PostgreSQL | 支持多 Schema | 支持 |
| SQL Server | 支持扩展属性注释、联合索引和约束 | 支持 |
| 其他数据库 | 表右键进入时按宿主能力展示基础字段 | 不提供 |

部分索引 / 约束接口失败时保留已读取字段并显示提示，不将读取失败伪装成「没有索引 / 约束」。字段查询失败提供重试。

MySQL / MariaDB 读取检查约束前先检查系统表是否存在；MySQL 5.7 等缺少该系统表的版本跳过查询，在约束页及导出文档中显示能力说明。检测结果在工作台会话内按连接和数据库缓存，失败结果不缓存；无需开启 debug SQL diagnostics。

## 安装

构建并打包：

```bash
npm install
npm run build
dbx-plugin package .
```

产物为 `dist/com.sazs.dbdoc-0.4.39-universal.dbxp` 及对应 artifact metadata；同包包含 macOS / Windows / Linux 各自 x64 / arm64 的后端，启动器自动选择，用户只安装一个文件，不需要 Go、Rust 或其他运行时。候选包未签名，可在 DBX 插件中心开启「允许安装未签名开发包」后安装。插件 ID 和发布者保持不变；升级后关闭并重新打开数据库文档工作台。文档切换页保留全宽列表、连接名称、长名称换行和窄屏展示，支持按数据库或连接名称搜索。

## 开发和验收

```bash
npm run check      # Svelte / TypeScript 检查
npm test           # Vitest 回归测试
npm run build      # 发行 UI，成功写入后输出 DBX_UI_BUILD_SUCCESS
npm run watch      # 每次成功增量构建也输出宿主重载标记
npm run preview    # 127.0.0.1:8807，官方契约形态的模拟宿主
dbx-plugin dev --path . --port 5190
```

模拟宿主仅由 `repro/server.cjs` 注入，不进入发行包。可通过以下地址复现功能和失败路径：

| 地址参数 | 场景 |
| --- | --- |
| `?picker=1` | 三个最近连接、同一连接多个数据库归组、无上下文的选择页 |

## 当前限制

- 目录、字段搜索和单表元数据查询受宿主每次 5,000 行 / 8 MiB 的上限约束；实际截断会显示提示。
- 会话目录缓存最多 8 份，详情缓存最多 64 张表，按最近使用顺序淘汰；刷新会清除当前库会话缓存并重新同步全部表。持久离线文档独立保存全库表结构，不受会话详情缓存容量影响。
- 单次只读查询受宿主 60 秒上限约束，插件 65 秒兜底超时。
- PostgreSQL 不枚举其他数据库；切库需已有对应 DBX 会话。
- PostgreSQL 11 及以下、MySQL 5.7.5 及以下的生成列元数据接口可能不兼容。
- Linux MySQL 同库仅大小写不同的表可能受 INFORMATION_SCHEMA 比较规则影响。
- UI 当前提供中文文案；宿主语言切换不会自动翻译插件。

## 源码

- `src/lib/bridge.ts`：宿主契约、能力位、存储、剪贴板和文件传输。
- `src/lib/store.ts`：有容量限制的缓存、元数据加载、字段搜索和导出队列。
- `src/lib/dialects/`：MySQL / PostgreSQL / SQL Server 的只读元数据 SQL。
- `src/lib/display/`：目录过滤 / 虚拟窗口、索引分组、展示工具。
- `src/ui/`：工作台、目录、详情、引导和模态框。
- `ui/`：发行构建产物；`repro/`：模拟宿主。

## 快照目录与单包存储（0.4.28）

默认使用宿主提供的插件数据目录下的 `documents-v2`，可自动读取 0.4.26 的原生缓存。从文档页或切换页顶部点击「快照目录」，填写绝对路径并点击「保存目录」即可切换；留空使用默认目录，新目录会自动创建。更换目录会先复制已有快照，目标目录的同名文件和原目录文件保留；复制失败不会切换配置。

目录配置保存在插件数据目录的 `snapshot-locations.json`，不占 UI 存储。所有快照复制成功后才切换默认目录；切换中断、UI 存储满或偏好丢失，重启后仍使用上次完成配置的目录。恢复时核对目录稳定身份（Unix 设备与 inode，Windows 卷和文件 ID），从自描述快照重建文档入口。目录被替换、磁盘离线或权限不足时提供检查和重新配置入口；恢复过程不重建丢失的目录，不自动查询数据库。「停用此目录」保留所有文件，不回退旧目录。

每个数据库是独立、完整的 `dbdoc-<SHA256>.json` 文件，包含格式版本、缓存键和 gzip/base64 文档。分块读写使用完整 SHA-256 校验，写完后原子提交；整库同步及提交成功才更新缓存和成功时间，失败保留原快照。文档列表单独存储，索引保存中断时可从完整快照重建入口。侧栏宽度等小偏好继续使用 UI 存储。

旧 UI 缓存以及 0.4.26 的 `.cache` 文件可迁移，新文件成功保存后仍保留原副本。0.4.27 的快照格式不变；如用过该版本，可填写原快照目录继续读取，随后更换目录会复制已有新格式快照。

DBX 的实际技术栈为 Tauri 2 + Rust / Vue 3 + TypeScript。当前插件只使用原宿主能力，不声明 `host.directory:*`。单包的 Unix shell / Windows batch 启动入口沿用现有宿主兼容机制，内置六个无需额外运行时的 Go 存储程序。原生后端受操作系统文件权限限制；用户输入路径不等于取得系统隐私权限，也不能绕过 App Sandbox / AppContainer / Flatpak 等限制。当前普通桌面宿主无需额外目录授权接口。本机 DBX 安装未被修改；[host/README.md](host/README.md) 仅保留上一版可选方案供参考。

构建者需要 Node.js、Go（由 `go.mod` 固定工具链）和 Rust 1.90+。`npm run package` 交叉编译全部后端，用随仓库保存的官方底层 packager 源码一次打包；只输出一个通用包及其元数据，不需要平台参数。`npm run check`、`npm test`、`npm run test:backend`、`npm run build` 用于验证。实际包内启动器、快照目录与浏览器联调记录见 [docs/verification-0.4.28.json](docs/verification-0.4.28.json)。Windows / Linux 已交叉编译，实机执行仍待验收。
